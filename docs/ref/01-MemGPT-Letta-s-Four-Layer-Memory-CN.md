# MemGPT/Letta 四层记忆架构：像人脑一样记忆

[Extension: com.atlassian.confluence.macro.core/toc]
> 为什么 AI Agent 不能只靠 RAG？因为人脑也不是这样记东西的。

---

## 一个让你秒懂的类比

你试试回答这几个问题：

- 你叫什么名字？（不需要"搜索"，脱口而出）
- 昨天午饭吃了什么？（想一下就能想起来）
- 三年前某个周二下午做了什么？（大概率想不起来，除非那天发生了特别的事）

人类的记忆从来不是"把所有经历存进一个大数据库，需要时搜索"。人脑有层次——有些东西你永远不会忘（你的名字），有些东西最近还记得但慢慢会模糊（上周的会议），有些东西早就沉入了潜意识深处，只有特定的线索才能唤醒。

MemGPT（现在叫 Letta）的核心洞察就是：**AI Agent 的记忆也应该分层，而不是把所有东西扔进一个向量数据库**。

---

## 四层架构：从 L1 Cache 到磁盘

Letta 的论文标题叫 *"MemGPT: Towards LLMs as Operating Systems"*——把 LLM 当操作系统来设计。它借鉴了计算机的存储层级（L1 Cache → RAM → 磁盘），把 Agent 的记忆分成四层：

```
┌────────────────────────────────────────────────┐
│          L4: Recall Memory（临时查阅区）         │
│  ┌─────────────────────────────────────────┐   │
│  │      L3: Archival Memory（深层档案库）    │   │
│  │  ┌──────────────────────────────────┐   │   │
│  │  │   L2: Message Buffer（近期对话）   │   │   │
│  │  │  ┌───────────────────────────┐   │   │   │
│  │  │  │  L1: Core Memory（核心自我）│   │   │   │
│  │  │  └───────────────────────────┘   │   │   │
│  │  └──────────────────────────────────┘   │   │
│  └─────────────────────────────────────────┘   │
└────────────────────────────────────────────────┘

```

让我一层一层拆开讲。

---

## L1: Core Memory —— "我是谁"

**人类对应**：你的名字、你的职业、你喜欢什么、你讨厌什么、你的家人叫什么——这些事实你不需要"回忆"，它们就是你的一部分，随时可以脱口而出。

**在 Letta 中**：Core Memory 是一小块文本（通常只有几百个 token），**始终钉在 system prompt 里**。每次 LLM 推理时都能直接看到，不需要任何检索。

它由两个 block 组成：

- **Persona block**：Agent 自己是谁——"我是一个编程助手，我的风格是简洁直接"
- **Human block**：用户是谁——"用户叫张三，是后端工程师，偏好 Python，正在做一个电商项目"

```
[Core Memory - Human Block]
Name: 张三
Role: 后端工程师
Language: Python
Current Project: 电商平台重构
Preferences: 喜欢简洁的代码风格，讨厌过度抽象

```

### 为什么这一层如此重要？

因为它实现了**零延迟、零信息损失的精确召回**。

你问 Agent "我叫什么"，它不需要去搜索任何数据库，不需要做向量相似度计算，不需要等待网络请求——答案就在眼前的 prompt 里。这和你回答"你叫什么名字"一样快，一样确定。

用信息论的语言说：Core Memory 的容量极小（rate 很低），但信息损失为零（distortion 为零）。这是把最宝贵的"带宽"给了最重要的信息。

### Agent 自己管理自己的 Core Memory

Letta 最精妙的设计是：**Agent 自己决定 Core Memory 里放什么**。它通过两个 tool 来编辑自己的核心记忆：

- `` core_memory_replace(block, old_text, new_text) ``：修改已有内容
- `` core_memory_append(block, text) ``：追加新内容

当用户说"我最近换工作了，现在在字节跳动"，Agent 会自主调用 `` core_memory_replace ``，把 Human block 里的公司信息从旧的改成"字节跳动"。不需要任何外部系统来决定"这条信息重要吗"——Agent 自己判断，自己更新。

这就像人脑的自我认知更新：你搬了家，你不需要任何"外部系统"来帮你更新——你自然而然就知道自己现在住在哪里了。

## L2: Message Buffer —— "最近发生了什么"

**人类对应**：最近几天的记忆。你能清楚地记得今天早上的对话、昨天的会议内容，但越往前越模糊。

**在 Letta 中**：Message Buffer 是一个固定容量的滚动窗口，保存最近的对话消息。所有近期的用户消息和 Agent 回复都完整保留在这里，同样不需要检索——它们直接在 context window 中。

```
[Message Buffer - 最近 20 轮对话]
User: 帮我看看 auth 模块的 bug
Agent: 我检查了 auth.py，发现第 42 行的 token 验证有问题...
User: 修好了，现在帮我加个 rate limiting
Agent: 好的，我建议在 middleware 层加...
...

```

### 溢出时怎么办？

Message Buffer 有固定容量。当新消息进来、旧消息要被挤出去时，Letta 不是简单地丢弃——它会先对即将溢出的消息做**摘要总结**，然后把摘要存入 Archival Memory，再释放空间。

这就像你的近期记忆：你不记得上个月每一天的每一句话，但你记得"上个月我们完成了认证系统的重构"——细节模糊了，要点还在。

关键点：**eviction（淘汰）不是遗忘，而是有意识的压缩**。摘要保留了信息的骨架，只是丢失了细节。

## L3: Archival Memory —— "我的一生"

**人类对应**：你的长期记忆库。几年前的一次旅行、大学时学的知识、曾经解决过的一个难题——这些记忆不在你的"工作台"上，但如果有人提到相关话题，你能"想起来"。

**在 Letta 中**：Archival Memory 是一个外部存储（通常是向量数据库），理论上容量无限。它存放：

- 从 Message Buffer 溢出的对话摘要
- Agent 主动存储的重要知识（通过 `` archival_memory_insert ``）
- 用户上传的文档、代码库等外部数据

但关键是：**Archival Memory 中的内容对 LLM 是不可见的**。它们不在 context window 中，LLM 不会自动看到。必须通过主动搜索才能取回。

```
# Agent 主动存储一条重要知识
archival_memory_insert(
    "项目在 2024年3月做了一次重大重构，从单体架构迁移到微服务。"
    "核心决策：用户服务、订单服务、支付服务拆分为独立服务。"
    "技术栈：FastAPI + PostgreSQL + Redis + RabbitMQ"
)

```

### 这一层的信息损失最高

用信息论的视角看：Archival Memory 的容量最大（rate 很高），但 distortion 也最高。不是因为数据本身被破坏了，而是因为：

1. **检索是近似的**：向量搜索只能返回"语义相似"的结果，不保证找到你真正需要的那条
2. **大部分记忆永远不会被访问**：就像你大脑中无数的记忆碎片，绝大多数一辈子都不会再被唤醒
3. **存储的是压缩后的摘要**：从 Message Buffer 溢出时已经做了有损压缩

## L4: Recall Memory —— "让我想想..."

**人类对应**：当有人问你"你还记得三年前那个项目吗"，你会在脑海中搜索一番，然后一些片段浮现出来——可能不完整，可能有些模糊，但足以回答问题。

**在 Letta 中**：Recall Memory 不是一个独立的存储，而是一个**临时检索缓冲区**。当 Agent 需要 Archival Memory 中的信息时，它调用 `` archival_memory_search(query) ``，检索结果被临时加载到 Recall Memory，然后注入当前的 context window。

```
Agent 内部思考：用户问到了之前的架构决策，我需要查一下...

调用：archival_memory_search("微服务架构 重构 决策")

Recall Memory 加载：
→ "项目在2024年3月做了一次重大重构，从单体架构迁移到微服务..."

Agent 回复：根据之前的记录，我们在2024年3月做了架构迁移...

```

这个过程就是信息的"解压缩"——从 Archival Memory 的海量存储中，按需提取一小部分，重新放回"工作台"（context window）上。

## 四层是如何协同工作的？

每一次 Agent 推理，它的 context window 由三个来源拼装而成：

```
Context Window = Core Memory（始终存在）
              + Message Buffer（近期对话）
              + Recall Memory（检索到的片段）
              ↓
              送入 LLM 做推理
              ↓
              生成回复
              ↓
              如果 Message Buffer 满了
              → 最老的消息被摘要后存入 Archival Memory
              如果发现了重要的新事实
              → Agent 调用 core_memory_replace 更新 Core Memory

```

这形成了一个持续运转的循环：信息不断地从外部流入 → 在不同层级间流动 → 重要的提升到内层 → 不重要的沉降到外层 → 需要时从外层检索回来。

## 为什么不能只用 RAG？

现在你应该能理解，"把聊天记录全部 embedding 后做向量搜索"只相当于 Letta 的 **L3+L4**——而且还是最粗糙的版本（没有 AI 压缩，没有结构化提炼）。

它缺了两个最关键的层：

1. **没有 L1 Core Memory**：用户的核心信息每次都要"搜索"才能找到。你的名字、你的职业、你的偏好——这些信息不应该需要搜索，应该始终可见。在纯 RAG 方案中，Agent 可能搜到一条三年前你说"我是学生"的记录，而忽略了你最近说"我已经工作了"——因为向量相似度不区分时效性。
2. **没有 L2 Message Buffer 的智能管理**：纯 RAG 对当前对话没有特殊处理，要么全塞进去（token 爆炸），要么随意截断（丢失上下文）。Letta 的 Message Buffer 有明确的容量管理和优雅的溢出策略。

**Letta 的四层架构告诉我们：好的记忆系统不是"存得多、搜得准"那么简单。它需要的是层次化的信息管理——最重要的信息零延迟直达，次重要的按需检索，细节可以容忍损失。** 这和人脑的记忆层次惊人地一致：核心自我 → 近期经验 → 长期档案 → 按需回忆。

---

## 一句话总结

> **Core Memory 是"我是谁"，Message Buffer 是"刚才发生了什么"，Archival Memory 是"我的全部经历"，Recall Memory 是"让我想想那件事"。四层协同，才是完整的记忆。**
